# recall

`recall` is a self-hosted document recall service for the terminal. It combines
a Go HTTP API, a Cobra-based CLI, local file storage, and PostgreSQL metadata so
personal notes can be uploaded, searched, and opened from any machine that can
reach the server.

The project is currently in an early milestone. The core upload, list, and get
flows are present; authentication, tags, terminal selection, Docker, Kubernetes,
and CI are already represented in the repository.

## Features

- HTTP API for document upload, metadata lookup, search, and content download.
- CLI client with `init`, `upload`, `list`, and `get` commands.
- Bearer-token authentication for every endpoint except `/health`.
- PostgreSQL metadata with title/tag search and soft-delete filtering.
- Local filesystem blob storage partitioned by UUID prefix.
- Type-safe database access generated by [sqlc](https://docs.sqlc.dev/).
- Versioned database migrations managed by [goose](https://pressly.github.io/goose/).
- Terminal UI flows built with Bubble Tea, Bubbles, Lip Gloss, and Glamour.
- Docker, docker compose, Kubernetes manifests, and Woodpecker CI pipelines.

## Architecture

```text
┌──────────────┐          ┌─────────────────┐          ┌────────────┐
│  recall CLI  │ ──HTTP──▶│  recall server  │ ──SQL──▶ │ PostgreSQL │
│ (cmd/recall) │          │  (cmd/server)   │          └────────────┘
└──────────────┘          │                 │          ┌────────────┐
                          └─────────────────┘ ──FS──▶  │  storage/  │
                                                       └────────────┘
```

| Path | Purpose |
| --- | --- |
| `cmd/server` | HTTP server entrypoint and graceful shutdown wiring. |
| `cmd/recall` | CLI entrypoint and Cobra commands. |
| `internal/api` | Shared JSON response contracts. |
| `internal/client` | Authenticated HTTP client used by the CLI. |
| `internal/config` | Server configuration loaded from environment variables. |
| `internal/handlers` | HTTP routing, middleware, response helpers, and document handlers. |
| `internal/storage` | Filesystem-backed document blob storage. |
| `internal/storage/database` | sqlc-generated queries plus database pool setup. |
| `internal/storage/queries` | SQL query definitions consumed by sqlc. |
| `internal/storage/schemas` | goose migrations for the PostgreSQL schema. |
| `internal/tui` | Terminal UI models used by CLI commands. |
| `k8s` | Kubernetes manifests for the server and PostgreSQL. |
| `.woodpecker` | CI/CD pipelines for lint, test, security scan, build, and deploy. |
| `docs` | Project-level documentation and file inventory. |

See [docs/PROJECT_STRUCTURE.md](docs/PROJECT_STRUCTURE.md) for a file-by-file
guide.

## Prerequisites

- Go 1.26.2 or newer.
- Docker, or a local PostgreSQL 16 instance.
- [`goose`](https://pressly.github.io/goose/) for migrations:

  ```bash
  go install github.com/pressly/goose/v3/cmd/goose@latest
  ```

- [`sqlc`](https://docs.sqlc.dev/) when changing SQL queries or schema files.
- `make`.

## Configuration

The server loads `.env` from the current directory as a convenience, then reads
environment variables. The CLI reads, in order of practical use: flags, `RECALL_*`
environment variables, `.env`, and `$HOME/.config/recall/config.yaml`.

| Variable | Used by | Default | Description |
| --- | --- | --- | --- |
| `DB_URL` | server | required | PostgreSQL connection string. |
| `AUTH_TOKEN` | server | required | Bearer token accepted by the API. |
| `SERVER_HOST` | server | `localhost` | Host/IP address the server binds to. |
| `SERVER_PORT` | server | `8080` | Port the server listens on. |
| `STORAGE_PATH` | server | `./storage` | Directory where uploaded file blobs are stored. |
| `RECALL_SERVER` | CLI | required | Base URL of the recall server. |
| `RECALL_AUTH_TOKEN` | CLI | required | Bearer token sent by CLI requests. |

The CLI also accepts `--server` and `--auth-token` to override configuration per
command.

## Quickstart

```bash
git clone https://github.com/PedroEvaldt/recall.git
cd recall

# 1) Configure local environment values.
cp .env.example .env

# 2) Start PostgreSQL.
make db-up

# 3) Apply database migrations.
make goose-up

# 4) Run the server.
make run-server

# 5) In another terminal, create or update the CLI config.
go run ./cmd/recall init

# 6) Upload and retrieve documents.
go run ./cmd/recall upload notes/go-structs.md --title "Go structs" --tags go,types
go run ./cmd/recall list "go struct"
go run ./cmd/recall get "go struct"
```

## CLI Usage

```text
recall [command] [flags]
```

### `init`

Create `$HOME/.config/recall/config.yaml`. If no token is provided in the TUI,
the command generates a random token that must also be configured on the server
as `AUTH_TOKEN`.

```bash
recall init
```

### `upload`

Upload a local file. The server stores the file under `STORAGE_PATH` and stores
metadata in PostgreSQL.

```bash
recall upload <file> [-t title] [--tags tag1,tag2]
```

| Flag | Description |
| --- | --- |
| `-t, --title` | Document title. Defaults to the filename without extension. |
| `--tags` | Comma-separated tags sent as searchable metadata. |

### `list`

Search documents by title or tag, or list all non-deleted documents.

```bash
recall list <query...> [-l limit]
recall list --all [-l limit]
```

| Flag | Description |
| --- | --- |
| `-l, --limit` | Maximum number of results. `0` means no explicit limit. |
| `-a, --all` | List all documents instead of searching by query. |

### `get`

Search for documents, select one in the terminal UI, then print or render its
content. Markdown files are rendered with Glamour; other files are streamed to
stdout.

```bash
recall get <query...>
```

### Global Flags

| Flag | Description |
| --- | --- |
| `-s, --server` | Server URL. Overrides `RECALL_SERVER`. |
| `--auth-token` | Bearer token. Overrides `RECALL_AUTH_TOKEN`. |

## HTTP API

All endpoints except `/health` require:

```text
Authorization: Bearer <AUTH_TOKEN>
```

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/health` | Liveness/readiness endpoint. Does not require authentication. |
| `POST` | `/documents` | Upload a document using multipart fields `title`, `tags`, and `file`. |
| `GET` | `/documents?q=<term>&limit=<n>` | List documents matching title or tags. Omit `q` to list all. |
| `GET` | `/documents/{id}` | Return document metadata as JSON. |
| `GET` | `/documents/{id}/content` | Stream the stored document content. |

Successful document responses use the shape defined in `internal/api/types.go`:

```json
{
  "id": "311ec9da-87c2-45c1-a4f2-d7b0cf60bf35",
  "title": "Go structs",
  "mime_type": "text/markdown",
  "filename": "go-structs.md",
  "tags": ["go", "types"],
  "created_at": "2026-04-29T01:17:23Z"
}
```

Errors are returned as JSON:

```json
{
  "error": "message"
}
```

## Development

### Makefile Targets

| Target | Action |
| --- | --- |
| `make db-up` | Start the PostgreSQL container. |
| `make db-down` | Stop the PostgreSQL container. |
| `make db-shell` | Open a `psql` shell in the PostgreSQL container. |
| `make goose-up` | Apply database migrations. |
| `make goose-down` | Roll back the latest migration. |
| `make goose-status` | Show migration state. |
| `make run-server` | Run the server with `go run`. |
| `make build` | Build server and CLI binaries into `bin/`. |
| `make install` | Install the CLI into `$GOBIN` or `$GOPATH/bin`. |

### Regenerating Database Code

After editing `internal/storage/queries/*.sql` or
`internal/storage/schemas/*.sql`, regenerate the typed accessors:

```bash
sqlc generate
```

Generated files in `internal/storage/database` should not be edited manually.

### Useful Checks

```bash
go fmt ./...
go test ./...
go vet ./...
```

`go fmt` formats Go files. `go test` runs package tests. `go vet` performs
static checks for common Go mistakes.

## Deployment

- `Dockerfile` builds a static `recall-server` binary and packages it in Alpine.
- `docker-compose.yml` provides a local PostgreSQL 16 database.
- `k8s/postgres.yaml` defines the PostgreSQL secret, PVC, deployment, and service.
- `k8s/recall.yaml` defines the server deployment and service. The API secret is
  intentionally not committed and must be created in the target cluster.
- `.woodpecker/*.yaml` runs CI checks, builds/pushes the image, and deploys to
  Kubernetes on pushes to `main`.
