# recall

> A self-hosted second brain for the terminal — store, search and retrieve your personal notes from anywhere.

`recall` is a small Go service plus CLI that lets you upload personal notes and summaries to a server you control (a Raspberry Pi, a VPS, your laptop) and pull them back from any terminal that can reach it. The goal is fast, offline-friendly access to material you already know but want to refresh quickly while coding.

> **Status:** first milestone. Expect rough edges in error handling and missing flags — see the [Roadmap](#roadmap).

## Features

- HTTP API for document upload, search and retrieval
- CLI client (`recall upload`, `list`, `get`) that talks to the server
- PostgreSQL-backed metadata with case-insensitive title search
- Local file storage for the actual document blobs
- Type-safe queries generated by [sqlc](https://sqlc.dev/), versioned migrations via [goose](https://github.com/pressly/goose)
- Graceful shutdown on the server, configurable timeouts on the client

## Architecture

```
┌──────────────┐          ┌─────────────────┐          ┌────────────┐
│  recall CLI  │ ──HTTP──▶│  recall server  │ ──SQL──▶ │ PostgreSQL │
│ (cmd/recall) │          │  (cmd/server)   │          └────────────┘
└──────────────┘          │                 │          ┌────────────┐
                          └─────────────────┘ ──FS──▶  │  storage/  │
                                                       └────────────┘
```

| Path                          | Purpose                                          |
|-------------------------------|--------------------------------------------------|
| `cmd/server`                  | HTTP API server                                  |
| `cmd/recall`                  | Cobra-based CLI client                           |
| `internal/api`                | Shared JSON response types                       |
| `internal/client`             | HTTP client used by the CLI                      |
| `internal/handlers`           | HTTP route handlers                              |
| `internal/storage`            | Local file store                                 |
| `internal/storage/database`   | sqlc-generated database access                   |
| `internal/storage/queries`    | sqlc query definitions                           |
| `internal/storage/schemas`    | goose migrations                                 |

## Prerequisites

- Go 1.26 or newer
- Docker (or a local PostgreSQL 16)
- [`goose`](https://github.com/pressly/goose) for migrations:
  ```bash
  go install github.com/pressly/goose/v3/cmd/goose@latest
  ```
- `make`

## Quickstart

```bash
git clone https://github.com/PedroEvaldt/recall.git
cd recall

# 1) Configure environment
cp .env.example .env

# 2) Start PostgreSQL
make db-up

# 3) Apply migrations
make goose-up

# 4) Run the server (keep this terminal open)
make run-server

# 5) Install the CLI globally
make install        # places `recall` in $GOBIN / $GOPATH/bin

# 6) Use it from any terminal on the same machine / network
recall upload notes/go-structs.md --title "Go structs"
recall list "go struct"
recall get "go struct"
```

## Configuration

All configuration is via environment variables. A `.env` file in the working directory is loaded automatically (both by the server and by the CLI).

| Variable        | Used by | Default      | Description                                  |
|-----------------|---------|--------------|----------------------------------------------|
| `DB_URL`        | server  | _required_   | PostgreSQL connection string                 |
| `SERVER_PORT`   | server  | `8080`       | Port the HTTP server listens on              |
| `STORAGE_PATH`  | server  | `./storage`  | Directory where file blobs are stored        |
| `RECALL_SERVER` | CLI     | _required_   | Base URL of the recall server                |

The CLI also accepts `--server` (or `-s`) to override `RECALL_SERVER` per command.

## CLI usage

```
recall [command] [flags]
```

### `upload`

Upload a file. The server stores the blob under `STORAGE_PATH/<uuid><ext>` and indexes the metadata in Postgres.

```bash
recall upload <file> [-t title]
```

| Flag             | Description                                                |
|------------------|------------------------------------------------------------|
| `-t, --title`    | Title for the document. Defaults to the filename stem.     |

### `list`

Search documents by title (case-insensitive substring) and print a numbered summary.

```bash
recall list <query...> [-l limit]
```

| Flag             | Description                                                |
|------------------|------------------------------------------------------------|
| `-l, --limit`    | Maximum number of results to print. Default: `10`.         |

### `get`

Fetch the first matching document and stream its raw contents to stdout (interactive selection is on the roadmap).

```bash
recall get <query...>
```

### Global flags

| Flag             | Description                                                |
|------------------|------------------------------------------------------------|
| `-s, --server`   | Server URL. Overrides `RECALL_SERVER`.                     |

## HTTP API

| Method | Path                  | Description                                              |
|--------|-----------------------|----------------------------------------------------------|
| `GET`  | `/health`             | Liveness probe                                           |
| `POST` | `/documents`          | Upload a document (multipart form: `title`, `file`)      |
| `GET`  | `/documents?q=<term>` | List documents whose title matches `term`                |
| `GET`  | `/documents/{id}`     | Stream the document contents (with original `MIME-Type`) |

Successful responses for `POST` and `GET /documents` use the shape defined in `internal/api/types.go`:

```json
{
  "id": "311ec9da-87c2-45c1-a4f2-d7b0cf60bf35",
  "title": "Go structs",
  "mime_type": "text/markdown",
  "filename": "go-structs.md",
  "created_at": "2026-04-29T01:17:23Z"
}
```

Errors are returned as `{"error": "<message>"}` with an appropriate HTTP status.

## Development

### Makefile targets

| Target              | Action                                                |
|---------------------|-------------------------------------------------------|
| `make db-up`        | Start the PostgreSQL container                        |
| `make db-down`      | Stop the PostgreSQL container                         |
| `make db-shell`     | Open a `psql` shell in the container                  |
| `make goose-up`     | Apply database migrations                             |
| `make goose-down`   | Roll back the latest migration                        |
| `make goose-status` | Show migration state                                  |
| `make run-server`   | Run the server with `go run`                          |
| `make build`        | Build server and CLI binaries into `bin/`             |
| `make install`      | `go install` the CLI to `$GOBIN` / `$GOPATH/bin`      |

### Regenerating database code

After editing files in `internal/storage/queries/` or `internal/storage/schemas/`, regenerate the typed accessors:

```bash
sqlc generate
```

## Roadmap

This is the first milestone — minimal upload / list / get. Planned next:

- Standardized error handling and exit codes
- Tags and richer metadata, with multi-field and full-text search
- Server-side pagination and limits
- Interactive selection in `recall get`
- Authentication for multi-user deployments
- Container image for one-shot Raspberry Pi deploys
